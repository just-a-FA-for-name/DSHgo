# V1.3 验收记录

V1.3 基于 1.2.1-test.1 候选修复发布。以下真机证据来自该候选版；正式包同步版本号为 1.3（versionCode 6）。不能将未复现的问题标记为彻底解决。

## 本次改动

- 网络回调只比较实际选中的物理承载网络；后台蜂窝网络的出现/退出不再直接触发页面重连或重复配置 VPN/DNS。
- 保留 HTTP 双向探测：真正断网仍重连；单纯网络提示、健康 OPEN WebSocket、业务 4xx/5xx 不伪造 offline/online。认证、限流、服务错误独立显示。每故障周期的无按钮 fallback 只派发一次，避免反复打断工作台自身退避。
- 内核 socket 绑定改用 ParcelFileDescriptor.fromFd + Network.bindSocket 的公开 API，关闭的只是复制 fd，不再反射隐藏字段。
- 不再默认强加 COOP/COEP。保留上游响应策略；如特定环境需要额外隔离，可在测试后显式设置电脑环境变量 DSH_PHONE_CROSS_ORIGIN_ISOLATION=1。不能把这些响应头当成 WebView 已支持 SharedArrayBuffer 的证据。
- 电脑页面启动前补齐缺失的 Promise.withResolvers / AbortSignal.any；保留原生实现、Promise 子类、abort reason，及时清理监听。手机 UA 使用真实 WebView，避免伪装 Chrome 131。
- HTTP/IP 地址通过本应用的显式内网边界处理；允许 loopback、tailnet 和私有 LAN，公开地址仍要求 HTTPS。无自动 HTTP 降级，HTTPS 证书/SNI 校验保留。Android 的 XML 无法表达动态 CIDR，因此 XML 允许 HTTP，WebView 与原生发现/诊断请求再按 EndpointPolicy 检查。HTTP LAN 依赖可信局域网，优先使用 tailnet HTTPS。
- 电脑 CLI 自动优先检查实际桌面安装目录的 resources/runtime/cli/bin/dsh.cmd；Tailscale Serve 超时/权限失败按退避重试，只在 CLI 不存在时尝试另一可执行路径，避免每 30 秒重复等待同一个请求。
- 诊断显示内置隧道，删除“安装独立 Tailscale”和不存在的启动脚本提示。新增实际 MagicDNS DNS 配置存在标记、socket 绑定结果、实际网络变更、脚本/插件资源错误分类；仍只记录数字类别，不记录地址、聊天或凭据。

## 证据与验证边界

- 隔离复现原先健康连接收到网络回调后发送 offline/online；修复后健康 OPEN 流保持，不增加恢复事件。
- 39 项隔离回归已通过，包括真实 Chromium WebSocket/上传 Worker、丢失确认、只读重试、HTTP 业务错误、abort 监听清理、CLI 路径、Serve 退避和纯 Java 网络/HTTP 边界策略。
- 原测试按字符串切分启动段，CRLF 会破坏隔离；已规范化换行并添加边界断言。测试只监听临时回环端口。
- issue #5 的 WebView 150 卡脚本尚未在报告者设备复现；移除强加 COEP、兼容层及新增诊断是针对性修正，不能据此声称唯一根因已确认。
- issue #6 的“完全未进入隧道”尚未从报告单独证明；HTTP 策略、socket 绑定和 DNS 配置分别处理并新增观察信号，需要机型验证。
- 准备安装前须确认用户可中断手机 DSHgo；不要求 root，不清数据，不重启电脑 DSH，不改变手机全局网络设置。

## 一加无 root 真机验证（2026-10-30）

OnePlus PKX110，Android 16/API 36，Google WebView 156.0.8078.47。安装临时同签名测试构建，未清除数据；测试 instrumentation 只创建隔离页面，不打开或读取用户对话。

- SecureStore 实际调用公开 fd 复制/Network.bindSocket 成功，调用后原 fd 仍有效。
- 实际 WebView 经 USB 临时回环端口进入隔离桥接：压缩 HTML、同步插件脚本与模块入口正常加载，readyState=complete、启动标记和 body 均存在。
- 模拟缺失的 Promise.withResolvers/AbortSignal.any 后，兼容层正常工作，Promise 结果及 abort reason 正确。
- 在浏览器到隔离代理的 GET 连接注入两次 reset，第三次读取成功。
- POST 到达隔离上游并接收请求体后 reset，代理返回失败，不重复提交；测试上游计数 1。WebSocket 握手正常。
- 此结果不等于 Android 13/WebView 116、报告者 WebView 150 或真实运营商的端到端故障已经复现并验收；特别不能将浏览器内部对原始连接丢失的自动重试泛化为所有 POST 都绝不会重复。
- 电脑主进程、现有桥接与全局手机网络未重启或改动；测试只使用临时回环服务和专用 USB 端口，结束清理。

随后正常启动一加上的候选版，不读取页面内容，只读取本次新产生的数字诊断事件：约 14 秒进入网页正常状态，实际内核 socket 绑定成功；前台观察 138 秒，无新增异常/重连状态。这是当前正常网络观察，不能代替故障现场。

## 本地交付与安装

手机已覆盖安装非调试 1.2.1-test.1（versionCode 5），保留登录和设置。电脑已更新已安装插件，并先只重启桥接，确认新版启动脚本已提供。随后用户明确告知 DSH 没有任务并授权重启，已重启桌面端，加载完整插件更新。原插件文件保存在本地备份目录，未改动对话数据或全局网络设置。

正式版本更新说明见 RELEASE-v1.3.md。#5/#6 保留后续机型与复杂网络复测空间，不因发布版本就视为所有场景已验证。
